# Database Migrations Guide

Complete guide for managing database migrations with Alembic.

---

## 📋 Overview

This project uses **Alembic** for database schema migrations. All models are automatically detected and migrations are generated accordingly.

---

## 🚀 Quick Start

### Apply All Migrations

```bash
# Using Docker
make migrate

# Or locally
make local-migrate
```

### Create New Migration

```bash
# Using Docker (recommended)
make makemigration msg="add_user_avatar"

# Or locally
make local-makemigration msg="add_user_avatar"
```

### Rollback Last Migration

```bash
# Using Docker
make rollback

# Or locally
make local-rollback
```

---

## 📚 Alembic Commands

### Basic Commands

```bash
# Apply all pending migrations
alembic upgrade head

# Create new migration
alembic revision --autogenerate -m "description"

# Rollback one migration
alembic downgrade -1

# Rollback to specific revision
alembic downgrade <revision_id>

# View migration history
alembic history

# View current migration
alembic current

# Show migration details
alembic show <revision_id>
```

### Advanced Commands

```bash
# Rollback all migrations
alembic downgrade base

# Upgrade to specific revision
alembic upgrade <revision_id>

# Show all revisions
alembic revisions

# Merge two heads
alembic merge -m "merge heads" <head1> <head2>
```

## 📁 Migration Files

Migration files are stored in: `backend/alembic/versions/`

Each migration file contains:
- `upgrade()` function - Apply migration
- `downgrade()` function - Rollback migration

### Example Migration

```python
"""add user avatar column

Revision ID: abc123
Revises: def456
Create Date: 2024-01-01 12:00:00.000000

"""
from alembic import op
import sqlalchemy as sa

# revision identifiers
revision = 'abc123'
down_revision = 'def456'

def upgrade():
    # ### commands auto generated by Alembic ###
    op.add_column('users', sa.Column('avatar', sa.String(), nullable=True))
    # ### end Alembic commands ###

def downgrade():
    # ### commands auto generated by Alembic ###
    op.drop_column('users', 'avatar')
    # ### end Alembic commands ###
```

## 🎯 Best Practices

### 1. Always Test Migrations

```bash
# Test on local database first
make local-migrate

# Check migration was applied
alembic current
```

### 2. Review Auto-Generated Migrations

Before applying:
```bash
# Check what changes will be made
cat backend/alembic/versions/<latest_migration>.py
```

### 3. Keep Migrations Small

- One logical change per migration
- Easy to rollback
- Easy to understand

### 4. Never Edit Applied Migrations

- Creates new migration for changes
- Editing applied migrations breaks history

### 5. Test Rollbacks

```bash
# Always test rollback after creating migration
make rollback
make migrate
```

## 🐛 Troubleshooting

### Migration Fails

**Check database connection:**
```bash
echo $DATABASE_URL
```

**Check migration file syntax:**
```bash
python -m py_compile backend/alembic/versions/<file>.py
```

**View detailed error:**
```bash
alembic upgrade head --sql
```

### Migration Already Applied

**Mark as applied without running:**
```bash
alembic stamp <revision_id>
```

### Heads Are Different

**Merge heads:**
```bash
alembic merge -m "merge heads" head1 head2
```

### Need to Reset Database

**⚠️ WARNING: This deletes all data!**

```bash
# Drop all tables
alembic downgrade base

# Re-apply all migrations
alembic upgrade head
```

## 🔄 Deployment

### Docker Deployment

Migrations run automatically on container start:

```dockerfile
CMD alembic upgrade head && uvicorn app.main:app ...
```

### Manual Deployment

```bash
# SSH to server
ssh user@server

# Navigate to backend
cd /path/to/backend

# Run migrations
alembic upgrade head

# Restart application
systemctl restart backend
```

### CI/CD Deployment

GitHub Actions runs migrations automatically:

```yaml
- name: Run migrations
  working-directory: ./backend
  run: alembic upgrade head
```

## 📝 Common Scenarios

### Add Column

```bash
# 1. Add column to model
# 2. Generate migration
make makemigration msg="add_column_name"

# 3. Review migration
# 4. Apply
make migrate
```

### Remove Column

```bash
# 1. Remove column from model
# 2. Generate migration
make makemigration msg="remove_column_name"

# 3. Review (should drop column)
# 4. Apply
make migrate
```

### Rename Column

```python
# Manual migration needed
def upgrade():
    op.alter_column('table_name', 'old_name', new_column_name='new_name')

def downgrade():
    op.alter_column('table_name', 'new_name', new_column_name='old_name')
```

### Add Index

```python
def upgrade():
    op.create_index('ix_table_column', 'table_name', ['column'])

def downgrade():
    op.drop_index('ix_table_column', 'table_name')
```
